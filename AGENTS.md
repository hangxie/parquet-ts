# Engineering Standards (parquet-ts)

Read [issue #1](https://github.com/hangxie/parquet-ts/issues/1) for architecture and milestones.

## Code

- TypeScript-native core: no reflection, decorators, schema classes, or generated models. TypeScript types are API conveniences, never runtime requirements.
- Keep `strict` clean. No `any`, no `!`, no unchecked assertions.
- ESM only; `import type` for types, `.js` extension on relative imports.
- Preserve values losslessly (`INT64` → `bigint`, `BYTE_ARRAY` → `Uint8Array`). Precision loss is opt-in, never silent.
- Throw typed `Error` subclasses carrying decode context: offset, row group, column path, page, encoding, type. Never silently reinterpret an unsupported structure.
- Keep Node APIs (`node:fs`, `node:zlib`) in adapters; the core stays platform-neutral.
- `src/index.ts` is the entire public surface; anything else is internal and free to change.
- Comment intent, not mechanics. One-line TSDoc on declarations; longer reasoning goes in the body next to the code it explains.
- Source files under 300 LOC, never over 500; tests are exempt.
- Add dependencies only for non-differentiating infrastructure (Thrift, codecs, CRC, crypto). Parquet logic stays in-tree.

## Tests

- TDD: write the test first and watch it fail.
- `foo.ts` is covered by a colocated `foo.test.ts`; fixture and cross-implementation suites live in `tests/`.
- Table-driven (`it.each`) for core logic; in-memory sources and inline data over on-disk files.
- Round-trip everything; `assemble(shred(v))` must equal `v` for every supported schema.
- Use `toStrictEqual` so missing keys stay distinct from `undefined`.
- Maintain or improve coverage.

## Interoperability

This is the project's success criterion, not feature count. Files written by parquet-go and PyArrow must read here; files written here must read in parquet-go, PyArrow, and DuckDB. New format features need `tests/fixtures/` coverage for their nested and nullable cases, preferably generated by another implementation.

## Docs

- TSDoc on public APIs. `examples/` must type-check under `make lint`.
- Update `README.md` for behavioral changes, and the plan issue when scope shifts.
- Markdown: no hard line breaks (one source line per paragraph and list item), no tabs, two-space indent inside code blocks.

## Commits

- `make all` must pass before every commit.
- Commit as soon as a task's gates pass; do not wait to be asked.
- Conventional Commits, signed with GPG/SSH.
- No AI/agent attribution in repo artifacts — no `Co-Authored-By`, `Generated by ...`, or similar.
- Small, minimal commits; fold fixups into the commit they belong to. Lockfile updates stand alone.
- No breaking changes without migration notes.

## TODO.md

Track review items as `- [ ]` checkboxes. Commit source changes only, never `TODO.md`, then check the item off.
